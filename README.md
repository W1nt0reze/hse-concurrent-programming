# Бронирование мест

## Какие мониторы есть и что они защищают

У каждого места есть свой внутренний объект `SeatState`. Его монитор защищает
ссылку на бронь, признак продажи и список ожидающих это место. Для бронирования,
подтверждения или снятия сначала захватываются мониторы всех мест набора,
а уже потом проверяется и меняется состояние. Метод `status` использует
тот же монитор, поэтому не может увидеть изменение набора в середине операции.
Разные объекты `Seat` с одинаковыми координатами обращаются к одному `SeatState`.

У каждого вызова `holdOrWait` есть отдельный объект `Waiter`. На нём поток
выполняет `wait`, а его монитор защищает флаг `signalled`. Этот флаг нужен,
чтобы не потерять уведомление, если место освободилось перед вызовом `wait`.
При снятии или подтверждении брони уведомляются ожидающие именно её места.
Подтверждение будит их, чтобы они вернули `empty`: проданное место уже не освободится.
Для истечения брони используется `wait` с таймаутом до ближайшего `expiresAt`
на запрошенных местах. Фонового потока нет.

Монитор `lifecycle` защищает счётчик активных вызовов, выдачу номеров броней
и общий список ожидающих. Через него `shutdown` запрещает новые вызовы,
будит ожидающих и дожидается завершения уже начатых операций.
Флаг `stopped` объявлен как `volatile`, потому что читается и вне этого монитора.

## Почему невозможна взаимоблокировка

Индексы мест сортируются по возрастанию. Метод `withSeats` захватывает их
мониторы только в этом порядке. Например, если двум потокам нужны места
1 и 2, оба сначала захватывают место 1, затем место 2, даже если в их
наборах места перечислены по-разному. Поэтому они не могут удерживать
по одному месту и ждать друг друга.

При удержании мониторов мест можно взять монитор `Waiter`. При удержании
`lifecycle` тоже можно взять `Waiter`, но мониторы мест не захватываются.
Под монитором `Waiter` никакие другие мониторы не захватываются.
Получить цепочку блокировок, которая замыкается на себя, нельзя.

Перед ожиданием в `holdOrWait` все мониторы мест освобождаются.
Сам `wait` освобождает монитор `Waiter`, поэтому другой поток может
отправить уведомление. В `shutdown` вызов `lifecycle.wait()` также освобождает
монитор: заканчивающиеся операции могут уменьшить счётчик активных вызовов.
